TaskFlow - Task Tracker

A full-stack task management app. The Angular frontend lets you add, complete, filter and delete tasks, and shows a dashboard with progress. An ASP.NET Core Web API stores everything in SQL Server, so your tasks survive a page refresh.

Features
Dashboard with total, pending and completed counts
Progress bar showing the percentage of tasks completed
Recent tasks list (the 5 newest)
Add, tick/untick and delete tasks
Filter the task list by All, Pending or Completed
Loading and error messages, for example when the API is unreachable
Friendly 404 page for unknown URLs
Responsive layout for desktop and mobile
Tech stack
Frontend: Angular (standalone components), TypeScript, HTML, CSS, Angular Router, Signals, HttpClient
Icons: Bootstrap Icons, loaded from a CDN
Backend: ASP.NET Core Web API (C#) with Entity Framework Core
Database: SQL Server
How it fits together

Browser (Angular, localhost:4200) -> HTTP + JSON -> ASP.NET Core Web API (localhost:5182) -> Entity Framework Core -> SQL Server

The pages (Dashboard, Tasks) only read from and call the TaskStore.
TaskStore holds the task list (signals), calculates the counts and handles errors.
TaskApi builds the HTTP requests to the backend. It is the only file that knows the URLs.
The API address comes from the environment files, so it can differ between development and production.
The API allows requests from http://localhost:4200 through CORS.

API endpoints

Base URL: http://localhost:5182/api/TaskDetail

GET /api/TaskDetail - list all tasks
GET /api/TaskDetail/{taskid} - get one task
POST /api/TaskDetail - create a task
PUT /api/TaskDetail/{taskid} - update a task (the body must include the same taskID as the URL)
DELETE /api/TaskDetail/{taskid} - delete a task

Task shape (JSON):

{ "taskID": 1, "title": "Write the README", "createdAt": "2026-10-11", "isCompleted": false }

Fields:

taskID: number, the primary key, generated by SQL Server
title: string, up to 700 characters
createdAt: string, a short date such as 2026-10-11 (the database column holds 12 characters)
isCompleted: boolean, whether the task is done

ASP.NET Core converts C# PascalCase property names to camelCase in JSON, so the Angular model must use the camelCase names.

Getting started

Prerequisites:

Node.js (LTS) and npm
Angular CLI: npm install -g @angular/cli
.NET SDK 9 or later
Visual Studio 2022 or later, or the dotnet CLI
SQL Server (LocalDB, Express or a full instance)
1. Set up the backend
Open the API solution in Visual Studio.
In appsettings.json, set the connection string named DEVConnection to your SQL Server instance.
Create the database. In Tools > NuGet Package Manager > Package Manager Console, run: Update-Database Or from a terminal in the API project folder: dotnet ef database update
Run the API (F5) and note the port it listens on (see Properties/launchSettings.json).
Check it works by opening http://localhost:5182/api/TaskDetail in a browser. You should see [] or a list of tasks.
2. Set up the frontend
In src/environments/environment.development.ts, set the API address to match your running API: export const environment = { production: false, apiBaseUrl: 'http://localhost:5182/api' };
From the Angular project folder, install dependencies and start the app: npm install npm start
Open http://localhost:4200
Using the app
Dashboard (/dashboard): see counts, progress and recent tasks
All Tasks (/tasks): add a task, tick it off, filter, delete
Any other URL: shows the 404 page
Configuration notes
Environments: npm start uses environment.development.ts. A production build (ng build) uses environment.ts. Both files must have the same property names. Never put secrets in them, because they are bundled into the code that reaches the browser.
CORS: configured in the API's Program.cs. It must use exactly http://localhost:4200 (no trailing slash) and must come before UseAuthorization. Restart the API after changing it.
Protocol: if the API redirects HTTP to HTTPS (UseHttpsRedirection), browser preflight requests can fail. For local development, use the same protocol and port in apiBaseUrl that the API actually serves.
